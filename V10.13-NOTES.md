# V10.13 (final clean build)

## Clean slate
- One-time per device: removes every book, "Recently Deleted" item and reading statistic left by earlier test versions.
- One-time per account (flag stored on the Supabase account): deletes all old rows in `user_books`, so test/demo books can never come back from the cloud.
- Demo-flagged books are also removed from the cloud on every sync.

## Restore (account on a new phone)
- Sign-in on a new device downloads every book from the account (verified with an end-to-end test using a simulated Supabase).
- Sign-out now uploads anything not yet saved, then clears the local copy, so another person signing in on the same phone never sees or uploads your books.
- Books deleted while offline are removed from the cloud on the next sync (they no longer reappear).
- Restoring a JSON backup now also uploads the books to the account.
- Reading progress counts as a change when comparing device vs cloud.
- Settings → "Check cloud backup": uploads anything missing and confirms every book in the account is complete.
- Not synced (by design): reading statistics and "Recently Deleted" (they stay on the device).

## Listen: male voice + Amharic
- Cause: the page used the voices installed on the phone. Android has no Amharic voice, and phone voices carry no male/female label, so "Male" could not be matched.
- Fix: new serverless function `/api/tts` (Azure AI Speech) with real male/female neural voices: Amharic (Ameha / Mekdes), English, Arabic, French, Spanish, German, Italian, Portuguese, Japanese, Chinese.
- The Listen page shows "Female/Male voice (online, HD)" when the function is configured; otherwise it behaves exactly as before (device voices).
- Needs two Netlify variables: `AZURE_SPEECH_KEY`, `AZURE_SPEECH_REGION` (see AZURE-VOICE-SETUP-AM.md). Requires internet. Signed-in users only.
- Tests: `node --test tests/ai-routing.test.mjs tests/tts.test.mjs`.
